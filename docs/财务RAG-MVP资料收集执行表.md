# 财务 RAG Agent · MVP 资料收集执行表

> **毕设项目** | 目标用户：零财务基础大众 | 范围：全国统一政策 + 地方扩展（已内置河南郑州）
> **MVP 四大功能**：智能问答 · 税率计算 · 申报指引 · 申报材料生成
> **格式策略**：原文为 PDF → 保留 PDF；其余 → Markdown；地方数据 → JSON 结构化
> **知识库架构**：双层设计 —— `national/` 全国统一层（模块一~四）+ `cities/` 城市覆盖层（模块五）
> **📎 关联文档**：← `财务RAG-资料收集蓝图.md`（概念层）| → `财务RAG-资料收集预处理方案.md`（执行方案）→ `财务RAG-技术架构与Agent方案.md`（系统设计）

## 🏗 知识库双层架构（全国统一 + 城市覆盖层）

> 后续新增城市只需在 `cities/` 下按相同 schema 追加文件，全国层（模块一~四）不动。

```
RAG 知识库结构
├── national/                   # 全国统一政策（模块一~四，不可变）
│   ├── tax_law/               # 个人所得税法、增值税法等
│   ├── social_insurance_law/  # 社会保险法（法律层面）
│   ├── rates/                 # 全国统一的税率表 JSON
│   ├── filing_templates/      # 申报表模板 DOC/PDF
│   └── qa_corpus/             # 即问即答语料
│
├── cities/                    # 城市差异化覆盖（模块五，可插拔）
│   ├── zhengzhou/
│   │   ├── social_insurance.json   # 社保缴费比例+基数
│   │   ├── housing_fund.json       # 公积金政策
│   │   ├── medical_reimbursement.md  # 医保报销规则
│   │   ├── tax_operations.md       # 地方税务操作指引
│   │   └── local_policies.md       # 其他地方政策（Phase 2）
│   │
│   ├── beijing/               # 后续添加...
│   ├── shanghai/              # 后续添加...
│   └── _template/             # 新城市接入模板
│       ├── social_insurance.schema.json
│       └── housing_fund.schema.json
│
└── metadata/
    └── cities_index.json      # 城市索引：city_code → 政策版本号 + 生效日期
```

**Agent 查询路由逻辑**：
1. 识别用户问题是否涉及地域参数（社保/公积金/医保/操作流程 → 大概率命中城市层）
2. 若涉及 → 从用户上下文或输入中提取城市代码 → 路由到 `cities/{city}/` 对应文件
3. 若不涉及 → 从 `national/` 检索
4. 同一次回答中允许**双层混合检索**（如"郑州个税怎么报" = 个税法从 national 取 + 操作入口从 cities/zhengzhou 取）

## ⚠️ 毕设关键提醒

1. **时效性标注必做**：小规模纳税人增值税 1% 优惠到 2027.12.31，个税专项扣除标准可能再调整。每个 chunk 的 metadata 必须带 `effective_date` 和 `expiry_date`
2. **税率表别让 LLM 算**：税率计算走代码逻辑读取 JSON，不要依赖 RAG 检索 + LLM 推理 —— 算错一个数答辩直接翻车
3. **申报材料生成 = 表单字段映射**：本质是把用户输入的 key-value 填入申报表模板对应字段，逻辑可比做"智能填表"而非"AI 写文档"，更容易控制准确性
4. **来源可溯源**：答辩时老师必问"你的数据从哪来"，每条答案带上引用链接
